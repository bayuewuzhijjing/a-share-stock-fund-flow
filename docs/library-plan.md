# 个股与题材库协作方案

保持现有页面设计，不新增资料抽屉、页签或复杂入口。页面只负责把资金流、题材和个股展示清楚；公开资料由 GitHub 协作者通过 Pull Request 维护。

## 谁可以改什么

- `data/a_share_theme_pool.json`：维护题材、产业链分支和题材成员股。
- `data/a_share_watchlist.json`：维护默认核心自选股。
- 页面里的“手动加代码”：只影响当前本地实例，不会自动提交到公共仓库。

这样可以把“个人盯盘”和“公共资料”分开，避免每个用户的临时自选污染公共题材库。

## 添加一只股票

在 `a_share_watchlist.json` 的 `items` 中增加：

```json
{
  "code": "300308",
  "name": "中际旭创",
  "sector": "CPO / 光模块",
  "priority": "high"
}
```

字段只保留页面当前确实使用的内容：代码、名称、产业/题材和优先级。不要在这里写资金流数据，资金流由采集程序生成。

## 添加到现有题材

在对应主题的 `branches[].stocks` 中增加：

```json
{
  "code": "300570",
  "name": "太辰光",
  "sector": "CPO / 连接器与光器件",
  "priority": "medium"
}
```

一只股票可以属于多个题材，但同一个题材内不能重复。`branch` 表示产业链位置，`role` 表示该分支的角色，例如核心制造、上游器件或下游应用。

## 添加新题材

新题材必须同时提供：题材名称、别名、至少一个产业链分支，以及每个分支的角色和成员股。提交说明中写清楚：

- 为什么把它纳入科技题材池
- 每只成员股与该题材的关系
- 参考来源或公开资料链接
- 是否存在明显的主题炒作或业绩兑现风险

## Pull Request 规则

1. 一次 PR 尽量只改一个题材或一组高度相关的个股。
2. 不直接提交 `data/*.db`、日志、缓存或 API Key。
3. 先运行 `python tools/validate_library.py`。
4. PR 描述列出新增/删除的股票代码和资料来源。
5. 维护者确认代码、名称、题材归属和重复项后合并。

不建议开放网页端直接写公共库。公共库采用 PR 审核，个人新增采用本地手动加代码，规则简单且可追溯。
